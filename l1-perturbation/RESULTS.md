# Результаты ночи 2026-10-16: точный алгоритм наименьшего возмущения цен в ℓ_p

## Главное

Построен точный алгоритм для задачи: найти ближайшие к данным цены, при которых заданный вектор
выпусков y слабо разрешим. Возмущается каждая цена каждого года, то есть все 2·d·T параметров
коробки. Стоимость — одна взвешенная норма ℓ_p всего вектора отклонений, 1 ≤ p ≤ ∞.

Алгоритм на каждом шаге даёт:
- нижнюю границу LB ≤ OPT;
- верхнюю границу UB, которая достигается рациональным решением Q, проверенным точно;
- остановку за конечное число шагов с относительным зазором не больше ε.

На реальных данных он решает до оптимума 13 срезов из 15, включая 8 срезов BEA с d = 8 и T = 40 за
1–6 минут каждый. Раньше большую часть этих срезов решить не удавалось.

## Алгоритм

Каждая часть — известный метод из литературы. Новое — их сочетание и сертификат отказа через покрытия.

1. **Сведение к коробкам.** Задача равносильна минимизации возрастающей функции
   ‖c∘(α+β)‖_p на замкнутом вверх множестве полуширин коробок, проходящих один запрос к оракулу
   коробки. Это монотонная оптимизация.
2. **Метод полиблоков с мастер-задачей MILP.** Это алгоритм QA из Tuy–Al-Khayyal–Thach (2005), §4.4.
   - Минимум на кополиблоке ищется решателем MILP (HiGHS, бесплатный), а не перебором вершин.
   - Проекция точки мастер-задачи на границу идёт вдоль направления (1,…,1), как в Tuy (2000), с. 479.
   - Мастер-задача содержит знаки лет (однонаправленность) и отношения доминирования.
3. **Сертификат отказа и отсечения по покрытиям.** Это главный рычаг скорости.
   - При ответе «нет» точный оракул возвращает вектор Фаркаша λ и набор покрытий C.
   - Теорема: отказ сохраняется во всякой коробке, где все покрытия из C присутствуют.
   - Фильтр удаления оставляет минимальный набор C′, как у Codato–Fischetti (2006).
   - В мастер-задачу добавляется отсечение «хотя бы одно покрытие из C′ исчезло».
   - В относительной метрике q = (1+ε)p это отсечение линейно и точно. Это ваше предложение.
   - В логарифмической метрике e^z оценивается кусочно-линейно сверху и касательными снизу.
4. **Запрос с допуском δ.** Оптимум лежит на вырождениях, то есть на точных совпадениях координат.
   Точка мастер-задачи вычислена в плавающей арифметике и попадает на совпадение лишь приближённо.
   Поэтому вопрос задаётся о коробке v + δ·1 с δ = ε·UB/(4‖c‖). Она накрывает совпадение строго,
   а ответ «да» сразу даёт зазор не больше ε/4. Именно это заставило сходиться реальные данные.
5. **Решение строится один раз, в конце.** Внутри цикла верхняя граница — стоимость коробки
   ‖c∘max(α, β)‖_p. Она верна по теореме о сведении. В конце из лучшей коробки строится рациональное
   Q, и его слабая разрешимость проверяется независимо, в точной арифметике.

Из литературы следуют три вывода для главы.
- Множество допустимых полуширин замкнуто вверх, значит, совпадает с замыканием своей внутренности.
  Поэтому аппарат «существенных» решений Туя (2005) не нужен, и LB оценивает сам оптимум.

  сходились даже на крошечных примерах. Сходимость дают отсечения по покрытиям, использующие
  сертификат оракула.

## Фундаментальные причины численных сбоев и их устранение

| Симптом | Причина | Решение |
|---|---|---|
| Точка мастер-задачи «недопустима», нижняя граница стоит | Оптимум лежит на совпадении координат, а плавающая точка попадает на него лишь приближённо | Запрос в коробке v + δ·1 (п. 4 выше) |
| Стоимость поднятой коробки на 7·10⁻⁴ больше ожидаемой | Округление углов с абсолютным шагом 10⁻¹⁰, а в BEA есть цены порядка 3·10⁻⁶ | Округление с относительной точностью 10⁻¹² |
| Одна итерация длится 3 минуты | Точная проверка решения на широкой коробке, дроби со знаменателями до 10²⁸ | Верхняя граница по стоимости коробки, решение строится один раз; цены в данных — короткие дроби |
| Совпадения цен разрушаются округлением | Угол с нулевой полушириной тоже округлялся | Нулевая полуширина даёт угол, точно равный цене |
| Ступенчатые отсечения не описывают изогнутую границу | Из одного ответа «нет» следует только ортант под точкой | Отсечения по покрытиям из сертификата |
| Логарифмическая метрика сходится медленнее | Экспонента в углах требует приближения | Относительная метрика: углы линейны, отсечения точны |

## Для планирования статьи: оракулы и их связь

**Одна задача о конусе.** Все оракулы — экземпляры одной задачи:

> найти w ∈ cone{1_S : S слабо достижимо среди точек W} с lo ≤ w ≤ hi.

- **Слабая разрешимость** y при ценах Q: W = Q (T точек), lo = hi = y.
- **Запрос коробки** [L, U]: W — 2T углов (L_1..L_T, U_1..U_T), w(L_t) ≥ y_t ≥ w(U_t). По теореме
  об углах (`box_iff`, `path_of_corners` в `price-perturbation`) это равносильно существованию Q в
  коробке, при котором y слабо разрешим.

Коробка — не цикл вызовов оракула слабой разрешимости, а один вызов того же алгоритма на вдвое большем
наборе точек и с неравенствами вместо равенств. Поэтому «оракул коробки полиномиален относительно
оракула разрешимости» верно буквально: обе задачи сводятся к одной.

**Где это написано в tex.**
- Теорема об углах: `price-perturbation/tex/price-perturbation.tex`, §«Сведение к углам».
- Определение оракула, сертификаты, сложность при d = 2, генерация столбцов: там же, §«Алгоритм».
- Сравнение оракулов на данных: там же, §«Пример».
- Точная геометрия при любом d: `price-perturbation/tex/onesided.tex`, §«Точный оракул при любом d».
- Использование сертификата «нет»: `l1-perturbation/tex/l1-perturbation.tex`, §4.

Для статьи эти куски нужно собрать в одну главу об оракуле.

**Реализация** (одна на всё): `price-perturbation/perturb/exact_oracle.py`, `oracle_exact`.
- Генерация столбцов: основная задача — LP по найденным множествам, подзадача — MILP по множествам,
  удовлетворяющим неравенствам покрытий x_t ≤ Σ_{s∈A} x_s.
- Геометрия решается только точно, в рациональной арифметике. Кандидат S проверяется точными LP,
  найденные покрытия проверяются точно и добавляются лениво.
- Ответ «да» — множества и рациональные массы. Ответ «нет» — вектор Фаркаша λ и конечный набор
  покрытий C. Сертификат «нет» проверяется независимо: алгебра λ и одна 0/1-задача с целыми весами.
- Независимые проверки: `proj.is_weakly_reachable` (точное LP для одного множества) и
  `proj.oracle_brute` (перебор, для крошечных примеров).
- При d = 2 есть полиномиальный оракул через поток (`proj.oracle_flow`, `poly-hardness/planar.py`), но
  на практике он медленнее `oracle_exact`. При d ≥ 3 задача NP-трудна (`np-hardness/`).
- Устаревшие варианты в плавающей арифметике (`milp_oracle.py`) ломаются у вырождений. Это довод в
  статье в пользу точной геометрии.

**Что добавил этот проект.** Использование сертификата «нет» как структуры, а не как ответа:
отказ сохраняется во всякой коробке, где покрытия из C присутствуют (`not_boxCone_of_certificate`).
Отсюда комбинаторные отсечения Бендерса.

**Обход в интерфейсе оракула (технический долг).** `oracle_exact` строит C внутри себя (объект
`CoverCuts`), но возвращает только λ. `cover_conflict` в `l1pert/solve.py` поступает так:
1. повторно вызывает `oracle_exact` на той же коробке;
2. читает многоточечные покрытия этого вызова из кэша модуля `exact_oracle._HINTS[(n, d)]`, где
   оракул хранит их как подсказки для следующих вызовов;
3. добавляет покрытия с |A| = 1, то есть строгое доминирование, — их пересчитывает по W;
4. сам проверяет (F2) 0/1-задачей. Если проверка не прошла, отсечения нет.

Корректность от обхода не зависит, так как сертификат перепроверяется. Издержки:
- лишний запрос оракула на каждое отсечение;
- зависимость от побочного эффекта: формата и ключа `_HINTS`;
- кэш обрезан до 5000 покрытий, поэтому на больших задачах отсечение может пропасть.

Чистое решение: `oracle_exact` возвращает C в ответе «нет» рядом с λ (несколько строк в
`price-perturbation/perturb/exact_oracle.py`), и повторный вызов исчезает. Не сделано, так как файл
вне этой папки.

**Оракул при d = 2** (`price-perturbation/perturb/box.py`, `poly-hardness/planar.py`, Lean
`mem_indicatorCone_iff_flow` в `PolyHardness/FlowLP.lean`). Задача о конусе на 2T углах записывается
одним LP полиномиального размера.
- Граф цепочек: пути от источника к стоку — строго выпуклые ломаные слева-снизу от точек. Дуга несёт
  множества Out (вне области ломаной) и Bnd (на границе).
- Критерий: y в конусе ⇔ есть поток f ≥ 0 и g с w = Σ f_e 1_{Out e} + g, 0 ≤ g ≤ β Σ f_e 1_{Bnd e};
  β = 1 — слабая разрешимость, β = 0 — строгая. Для коробки добавляется w(L) ≥ y ≥ w(U).
- LP решается методом внутренней точки, без симплекса. «Да» сертифицируется разложением потока на
  множества с точными массами и построением Q. «Нет» сертифицируется рационализованным вектором
  Фаркаша и одним поиском самой тяжёлой цепочки (длиннейший путь в DAG).
- На практике медленнее `oracle_exact` (при T = 40 2–14 с против 0.8–3 с). Ценность — теоретическая:
  при d = 2 задача полиномиальна, при d ≥ 3 NP-трудна.

**Строгая разрешимость.** Все оракулы общей размерности проверяют слабую разрешимость. Точный оракул
строгой разрешимости есть только при d = 2: тот же поток с β = 0 (`planar.py`, `strict=True`). При
общей d его в текущих папках нет.

**Возможная структура статьи.**
1. Задача о конусе и её точный оракул: `price-perturbation` + `np-hardness/` + `poly-hardness/`.
2. Коробки и теорема об углах.
3. Максимум по годам — аналог индекса Африата: `price-perturbation`.
